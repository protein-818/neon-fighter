### 知っておくこと: 1行目は「外枠」

`03` の1行目は、ずっと前にアーティファクトから取り出したときに付いた外枠で、ゲームの一部ではない。

```
1行目: <!doctype html><html><head><meta charset=utf8><meta name=viewport …><style>:root{color-scheme:light…}</style></head><body>
2行目: <!DOCTYPE html>
3行目: <html lang="ja"><head><meta charset="utf-8">
```

つまりファイルの中に `<!doctype html>` が2回ある。ブラウザは2つ目を無視するので動きに問題は無く、V57 より前からこの形のまま来ている。アーティファクトに公開すると、この1行目に当たるものが外側にもう一度付く。

## 4. 分割で気をつける所

### 4-1. 仕組みそのもの

- **全部が1つの共通の場所にある**。`const`・`let`・`function` はどれも最上位で、ファイルを分けても連結すれば同じ1つの script になる。分けたファイルを別々の `<script>` や ES modules にすると動かない（`let`／`const` の共有と、取り決めの「script は1つ」のため）。
- **外付け部品と検証の道具は、最上位の `let`／`const` を外から読み書きしている**（`mode`、`ch`、`lv`、`SPECT`、`A`、`B` など）。関数や `{ }` で包むと外から見えなくなる。包まない。
- **`function` は上へ持ち上がるが、`const`／`let` は持ち上がらない**。関数どうしは順番を入れ替えても動くが、§3 の表の文と `const`／`let` の宣言は順番を変えない。
- **`'use strict'` を足さない**。いまは付いていない。足すと動きが変わる所があるかもしれず、確かめていない。
- **整形しない**。字下げや改行をそろえる道具（Prettier など）をかけるとバイト一致にならない。必要なら引っ越しのあとの別の変更にする。
- 文字コードは UTF-8、改行は LF。ソースの中に日本語と絵文字（🔇 📱 👁 ♪ など）がそのまま入っている。エディタやシェルで文字化けさせない。

### 4-2. 名前のまぎらわしさ

| 名前 | 注意 |
|---|---|
| `T` と `TT` と `TR` | `T` は試合のフレーム数。`TT` は描画用の時間（`loop` で入れる）。`TR` は訳す関数。「`T`＝翻訳」ではない |
| `ch` | 最上位の `ch` は**1Pが選んでいるキャラの番号**（取り決めの名前）。ところが `chainsBack`／`chainsFront` の中では `ch=(k,lx,…)=>` という別物、`ac()` の中のループ変数、`wrapT` の `for(const ch of …)` としても使われている。一括の置き換えをしない。技のデータの `ch:` は「凍えの増える量」でまた別 |
| `g` | 最上位の `g` は canvas の描画先。`tn nz bv bn bkick` などの音の関数と `ai` の中では別の意味の `g` を宣言している。技のデータの `g:` は必要ゲージ |
| `ac` | 最上位の `ac()` は音の準備。技のデータの `ac:` は持続フレーム |
| `D` | 197行の `D=()=>SDIST` は音の距離。関数の中では別の `D` をよく使う |
| `crowd` | 最上位は観客の声を鳴らす関数。`bgR` の中に同じ名前の別物がある |
| `K P L M` | 関数の中で何度も別の意味で使われる1文字の名前。最上位には無い |
| `A` `B` | 1Pと2P（またはCPU）の体。`start()` や `startTut()` のたびに作り直されるので、入れ物を覚えておかない |
| `AC` と `AC2` | `AC` は音の装置、`AC2` はループの時間の端数 |
| `selC` `selV` | 0＝ランダム、1以上＝「番号+1」。そのまま添字に使わない |

### 4-3. 動きのくせ

- **`p2w(fn)`（1129行）**: 2人対戦のキャラ選択で2Pの番のとき、`ch` を一時的に `ch2` と入れ替えて `fn` を呼び、終わったら戻す。同時に `P2S`（処理中の印）と `KP`（技表に出すキー）も入れる。メニューの関数を足すとき、`p2w` を通さずに `ch` を読むと2Pの番で1Pのキャラを見てしまう。
- **`uiSync`**: ふだんは空の関数で、スマホのときだけ 1139行のかたまりの中で本物に入れ替わる。タッチの部品の表示はここ。
- **`pop()`**: 画面に出す文字は基本的に出さない作りになっていて、トレーニング中の「OK!」だけ出る。道具は `pop` を差し替えて PARRY などを数えている。`pop` の呼び出しを消すと数えられなくなる。
- **計測用の数え口**: `BRK WND HXN ADN IBN CHF` は本体では宣言していない。`typeof X!='undefined'` で「あれば数える」だけ。宣言を足さない、行を消さない。
- **`Math.random` は描画でも使う**（画面の揺れ、火花、背景など）。乱数を固定した比較は、`update()` と `draw()` を呼ぶ順番と回数が同じでないと一致しない。分割だけなら変わらない。
- **時刻**: `Date.now()` を使うのは、音の案内の点滅（`drawAud`）と、戦績を消すときの「もう一度で消去」（`drawRiv`・`rivHit`）だけ。試合の進行は時刻を使わず、`loop(t)` が受け取る時間で 1/60 秒ずつ `update()` を回す。
- **`start()` は保存をする**: 難易度やキャラを `localStorage` に書き、`NFA.matchStart` を呼ぶ。道具から呼んでも本体は壊れないが、同じページで試合を重ねると戦績（`REC`）がたまり、CPU の攻め方と入場の台詞が変わる。比較は毎回同じ順で行うこと（道具はそうしている）。
- **外への通信**: Google Fonts だけ。読めなくても代わりの文字で動く。

### 4-4. 保存データの名前（変えない）

`nf2_lv`（難易度）、`nf2_ch`（キャラ）、`nf2_sv`（ステージ）、`nf2_cpu`（CPU）、`nf2_lang`（言語）、`nf2_rec`（戦績）、`nf2_col`（色）、`nf_aud2`（音）。

### 4-5. 公開側との取り決め（プロジェクトの指示と同じ。念のため）

- 外付け部品が読む名前を変えない: `mode paused tut SPECT A B win lv LV CH ch cv`、加えて `VS2 LANG TR NF_INPUT`
- キー入力は window の `keydown`／`keyup` で受け、割り当てを変えない
- script は1つ。ファイル末尾の形を変えない
- `NFA.matchStart`／`matchEnd`／`trainingStart` の呼び出しを消さない（`start` 280行、`ko` 290行、`startTut` 426行にある）
